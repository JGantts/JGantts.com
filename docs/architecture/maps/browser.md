# Kovyálo browser map

**Responsibility:** display the fictional world with configurable raster layers, towns, theme, compass, and layer-tree controls.

**Entry points:** `/kovyalo` and its dev/game variants mount `IndexView.vue`; `maps.ts` coordinates map setup and `initMapSourcesAndLayers` installs sources/layers.

**Dependencies:** MapLibre, PMTiles protocol, `/assets/maps/geo-data/regions.json`, [generated map assets](generation.md), reactive settings, and HUD GUI types.

**Consumers:** Kovyálo page/layout and map HUD components.

**Startup and graphics recovery:** the view catches map startup failures and offers an explicit page reload when graphics are unavailable; it does not repeatedly create contexts. Pending configuration requests and post-font startup are canceled on unmount. Removing a map cancels pending vector/raster helpers and prevents late theme watchers from being installed. Keyboard listeners, animation frames, and pending camera saves are cleaned up. MapLibre instances stay outside Vue’s deep reactivity. Context-loss/restoration events show and clear the recovery message.

**Small-screen controls:** at widths up to 640 px or heights up to 500 px, Layers and Settings collapse into buttons with one scrollable panel open at a time. A 64 px compass stays visible; the map uses the dynamic viewport height and HUD padding respects device safe areas. The compass dial and needle rotate together. Clicking or keyboard-activating it resets north; activating it again near north also levels the pitch.

**Full screen:** the HUD offers a full-screen toggle when the browser supports the Fullscreen API. It expands the map and its HUD together, resizes MapLibre on entry/exit, and tracks browser exits such as Escape.

**Initial view and layer memory:** first visits open at Ziemúnd (center `[-34.3927, 11.8405]`, zoom 6) with Political → National → Ziemúnd and Physical → Terrain → Rivers enabled. Enabled layer paths are saved alongside the camera and preferences in local storage (`app-settings`). Refreshes and later visits restore that selection, including an empty selection. Older saved settings without a layer selection receive the two defaults while retaining their saved camera. Layer changes do not create browser-history entries.

**Region labels:** named regions render their `title.native` and optional `title.latin`/`title.hangul` through the same language selector and ruby renderer as towns. Region names grow from 24 px to 32 px when zooming out and remain visible two zoom levels below the region’s display minimum. They win label collisions. Town names show normally within their region’s zoom range; only the two largest towns by population remain for one zoom level below its minimum, then all town names hide. Below the region minimum, town dots follow the labels actually placed after collision checks; unnamed towns have no dots. At detailed zooms, settlement markers use collision checks; minor settlements appear one zoom level later, and additional markers become visible as space allows. Region labels center on their bounds unless `labelCoordinates: [longitude, latitude]` is supplied. The World container is not labeled. Names are separate map symbols rather than lettering baked into raster artwork.

**Town labels:** points use a `title` object containing `native` for native spelling, optional `latin` for romanization, and optional `hangul` for a reading. Deployment derives `title.hangul` from `title.latin` in the served regions file; local development also loads compiled metadata with generated readings. The HUD persists six modes: Native, Native + Latin (the default), Native + Hangul, Native + Latin + Hangul, Latin, and Hangul. The three-language mode shows Latin beneath the native line; Hangul appears as fallback ruby for Hangul/CJK names without explicit ruby; otherwise it appears as a separate line beneath Latin. Missing readings are skipped. Native Hangul uses the bundled JGantts Hangul Serif Regular webfont, including centered short acute accents; native Latin/Han labels use Noto Serif and Noto Serif KR; Latin uses Noto Sans Light (300). Ruby and all below-native translations use Noto Sans Light with JGantts Hangul Sans Light for Hangul (Noto Sans KR remains a fallback). The patched fonts are restricted to Hangul and U+0301 by Unicode range, and is bundled through Vite so it does not depend on installed fonts or the separate map-asset deployment. Needed Unicode subsets load before labels are drawn. Preloading separates Hangul, CJK, and other text: patched fonts receive Hangul, KR fallbacks receive only Chinese/Japanese/Bopomofo and CJK punctuation, and the base Noto families receive other text. This avoids downloading KR Hangul subsets and duplicate KR Latin subsets that are never used. Primary labels use 18 px on small/short map views, 20 px from 768×500, 22 px from 1200×700, and 24 px from 1600×900 (CSS pixels; both dimensions must qualify). Map resize events update the size; fitted images scale ruby and translations proportionally while retaining native-only anchoring.

Explicit ruby comes from `{base|reading}` spans in `title.native`, such as `뚜괘 {日|초́까}그{北|핰́따}`. The native line displays `뚜괘 日그北`, with `초́까` over `日` and `핰́따` over `北`; surrounding text remains unannotated and combining accents are preserved. When a native name contains Hangul or CJK characters (Han, Hiragana, or Katakana) and no explicit ruby span exists anywhere in it, the entire `title.hangul` reading is centered as ruby above the entire native name. Explicit ruby always takes precedence; partial annotations are never replaced or supplemented by the fallback. Native and Native + Latin retain the explicit annotations. Hangul mode keeps the annotated native name when it contains Hangul; other names use the standalone `hangul` field. Native + Hangul uses the same explicit or fallback ruby for Hangul/CJK names without duplicating the reading below; Latin-script native names show Hangul underneath. Latin mode uses `latin` when nonblank, otherwise the resolved native label. Native + Latin adds any nonblank Latin field below at 80% size, including an identical spelling; a Latin-only entry uses that spelling as its primary label. Missing native or standalone Hangul labels remain empty in their respective modes.

Romanization uses 80% of the primary size; supplementary readings use 62%. Text halos use 5.5% of each line’s font size. Ruby appears at 55% size over explicit spans, or over the whole native name for fallback readings. Visible labels are high-resolution images with a content rectangle covering only the primary line. Their image pixel ratio exceeds the display ratio and covers the maximum 24 px label size, keeping MapLibre linear filtering active after zoom settles instead of switching to nearest-neighbor sampling. Invisible single-line text defines MapLibre variable anchors; both that text and the fitted image participate in collision checks, including translations and ruby outside the primary line. Placement tries eight directions with a one-em marker gap plus the actual ruby/translation overhang, hiding crowded names when no close placement fits; the fitted image places ruby above and Latin centered below without moving the native anchor. Ruby does not widen native character advances. Standalone Latin/Hangul modes anchor to their displayed spelling. An 8 px collision margin reduces crowding, prioritizing explicit capitals and then population. Invisible marker symbols reserve the visible marker footprint so labels cannot cover dots. Boundary-aware placement ranks the eight candidates by weighted overlap with visible national, provincial, and county lines, including a 5 px clearance. When every candidate crosses a boundary, it prefers the least overlap; MapLibre still enforces label and marker collisions. Candidate ordering refreshes after camera, viewport, language, theme, and layer changes.

**Cartographic styling:** [cartography.ts](../../../jgantts-com/src/views/kovyalo/maps/cartography.ts) groups label spacing, hierarchy, halos, political color/shadow adjustments, river opacity, boundary classes, and settlement sizes. Political raster colors receive a modest saturation reduction and a shadow floor; transparent pixels and black background layers retain their original treatment. Relief geometry and source colors remain unchanged. Rivers render after political fill and before boundaries. Generated river vectors use estimated contributing drainage area for gradual widths, rounded junctions, and thinner minor detail at low zoom. Opaque muted strokes avoid seams between width samples; fallback rasters retain reduced opacity. A temporary layer anchor preserves stacking order regardless of fetch timing. Ziemúnd’s display range extends through the map’s maximum zoom 10; data tiles still stop at zoom 10.

**Boundary classes:** Ziemúnd opts into generated national, provincial, and county linework using its political color raster as `boundaryGuide`. Rounded vector lines have zoom-aware widths and opacity; national/provincial strokes use a subtle light casing to retain contrast over dark terrain. All classes follow the original border layer’s GUI selection. The country outline also marks the transition to unexplored black territory; the source does not distinguish another legal category there. Other regions retain raster borders. Missing classified assets fall back to the original raster during independent site/map deployments.

**Settlement hierarchy:** optional `settlementClass` values are `capital`, `city`, `town`, and `village`. Explicit classes determine radius; absent classes use configurable population thresholds (500 for towns, 5,000 for cities). Population does not imply capital status. White markers retain a dark outline on every terrain color. Marker collision checks prioritize capitals and then population, preserving coordinates and progressively exposing crowded settlements as the map zooms in. Visible marker/label queries run after placement becomes idle, avoiding transient worker/placement mismatches during language and camera changes.

**Invariants:** browser layer paths must match Python's parent-region path construction and dark suffixes. Region bounds use latitude/longitude tuples and need conversion for MapLibre coordinates. Layer visibility combines GUI selection and theme metadata. Region IDs, parent IDs, zoom ranges, and UI paths form a cross-language contract. Ziemúnd enables 3D terrain from its generated Mapbox RGB height tiles, with 10× elevation exaggeration. The DEM source declares regional bounds and data maximum zoom 8, so higher camera zooms reuse existing tiles. Camera tilt reveals the relief; baked raster shading remains in use. Terrain configuration comes from the compiled region metadata, deployed alongside the tiles.
