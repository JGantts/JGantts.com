# Map asset generation

**Responsibility:** compile source raster layers and region definitions into browser map assets independently of the Node/Vite build.

**Entry points:** from `python/`, run `python3 make_all_tiles.py` or add `--dev`; tiler paths require that working directory. `tile_pm.py` builds one archive; terrain/rivers/color/erosion scripts are separate offline tools.

**Dependencies:** Python 3.10+ (including local metadata generation), `maps-sources/geo-data/regions.json`, raster inputs, Python requirements, GDAL tools, and PMTiles CLI.

**Automatic local builds:** Vite starts the incremental map builder with `--dev` on startup and watches map PNG/JSON sources and Python build scripts. Changes are debounced, builds run one at a time, and an edit during a build queues another pass. Successful builds refresh the preview; failures appear in the dev terminal and retry on the next source change. The existing Python/GDAL/PMTiles prerequisites are required.

**Classified boundary assets:** a single-image border layer can specify `boundaryGuide` (a sibling political layer ID) and `provinceCount`. Ziemúnd uses `states` and four provinces: the combined opaque footprint is the country, distinct hues identify provinces, and remaining border strokes are counties. [classify_boundaries.py](../../../python/classify_boundaries.py) writes `<layer>-classes.geojson` alongside the raster. Hue clustering ignores relief brightness; alpha preserves the country footprint. County strokes are skeletonized, with junctions reconnected to the existing parent boundary within six source pixels and line simplification limited to 0.6 source pixels. The source PNGs are retained. The browser renders the classified vectors with independent zoom-aware styling.

Install `python -m pip install -r requirements-cartography.txt` from `python/` for this compiler and its tests; full production tooling uses `requirements.txt` plus GDAL/PMTiles. Point Vite’s `PYTHON` environment variable at the prepared interpreter if the system interpreter lacks these packages. Classification caches include both source raster hashes, bounds, province count, and compiler source; missing GeoJSON triggers a rebuild independently of cached rasters. Test with `python -m unittest discover -s python -p 'test_*.py'` from the repository root.

**River network assets:** Ziemúnd’s river layer specifies `riverGuide: "rivers-network.json"`. The guide records eight visually reviewed short gaps between existing strokes and the existing southeastern lake outlet. [river_network.py](../../../python/river_network.py) skeletonizes `rivers.png`, clips display geometry to `base.png`’s opaque footprint, applies only those listed repairs, and requires one connected network. Repairs fail if their anchors drift more than two source pixels, exceed the guide’s maximum distance, or cross black territory. The supplied outlet must remain an endpoint inside the blue lake artwork. No new river course or terrain is generated.

The compiler estimates contributing area with a marker-controlled watershed of `height.png`, constrained to the mapped network. It accumulates area toward the reviewed lake outlet, splitting and recombining flux through braids without creating cycles. This is a cartographic runoff proxy, not measured discharge or a newly authoritative drainage map. Latitude-adjusted terrestrial area is conserved at the outlet; lake pixels do not contribute land area. The guide controls catchment resolution, display smoothing, and segment length. Raw accumulation remains separate from the smoothed display values, which drive gradual stroke widths. `<layer>-flow.geojson` includes a hydrology audit with conservation totals, repairs, clipped pixels, and outlet information. Cache keys include river, base, height, guide, bounds, and compiler hashes. Source artwork stays intact.

**Local metadata edits:** Vite serves the compiled `PUBLIC/assets/maps/geo-data/regions.json` without caching. Local builds generate Hangul for town and region titles, atomically replace the compiled metadata, and refresh the preview after success. Source metadata stays untouched. Name-only edits reuse cached rasters.

**Town metadata:** each point groups its names under `title`: `native`, optional `latin`, and optional generated `hangul`. Coordinates and population remain on the point.

**Deployment-generated Hangul:** after the raster build/cache steps, `build-maps` runs `python3 python/generate_town_hangul.py --output maps-rendered/geo-data/towns-hangul.generated.json --regions-output maps-rendered/geo-data/regions.json`. The separate town list retains all town data and source locations. The deployment copy of `regions.json` receives those readings in each town's `title.hangul` field, which the existing map label and font-loading paths consume. Both files are uploaded together as map artifacts; generated files are ignored by Git. Source `maps-sources/geo-data/regions.json` is never modified. Missing or unsupported Latin spellings fail the deployment generation before writing either file; old readings are never reused. The generator requires an explicit output path for standalone CLI use. The local raster builder also compiles readings when run with `--dev`.

The [converter](../../../python/generate_town_hangul.py) uses the custom romanization chart (`tt` → `ㅋ`, `h` → `ㅎ`, `tc/dc` → `ㅈ/ㅉ`, and `w/j` glides), longest spelling matches, silent `ㅇ` for vowel-only syllables, and `ㅡ` for consonants without vowels. The spelling `em` supplies `ㅡ` plus the `ㅁ` coda (`kem` → `금`, `em` → `음`); standalone `e` is invalid. The vowel spellings `ie`, `ae`, and `oe` are unchanged. A consonant before a vowel starts the next syllable; otherwise it becomes a single coda when representable, or starts a syllable with `ㅡ`. Apostrophes force boundaries (`loega'k` → `초까그`, versus `loegak` → `초깍`). Whitespace is preserved and case is ignored. Acute-accented vowels use the same spelling as their unaccented equivalents; the resulting complete Hangul syllable is followed by U+0301 COMBINING ACUTE ACCENT (`lóega'k` → `초́까그`). Precomposed and decomposed Latin accents are equivalent, including accents within vowel digraphs and glides. Other diacritics and spellings absent from the chart are flagged rather than inferred from the previous spelling system. Glide vowels must match the chart (`w`/`j` cannot stand alone). Verify with `python3 -m unittest discover -s python -p 'test_generate_town_hangul.py'`.

**Consumers:** [browser map](browser.md) and the workflow's `build-maps` and `deploy-maps` jobs.

**Incremental CI builds:** `build-maps` restores `maps-rendered/` together with `build_hashes.json` from the last compatible GitHub Actions cache after checkout. Cache compatibility includes runner OS/architecture and Python source/dependency hashes; the saved cache key uses the generated render manifest. Metadata-only changes (town names, Hangul/Latin readings, populations, coordinates, UI labels, display zooms) preserve compiled assets and do not save a duplicate cache. The builder always copies the current `regions.json`; the subsequent deployment generation step fills its Hangul fields before artifact upload, even when all rasters were cached. Raster, bounds, data zoom, or layer-type changes rebuild the affected outputs; missing outputs rebuild even when their saved hashes match. A cold, expired, or incompatible cache requires a full build. Keep both generated images and their manifest when restoring local builds as well.

**Retrying uploads:** `build-maps` saves the generated tree as a GitHub artifact retained for 30 days and passes its artifact ID to `deploy-maps`. Deployment downloads that exact artifact into a clean checkout before SCP. Re-run the failed deployment job to reuse a successful build without invoking Python/GDAL again. A full workflow rerun builds and saves a new artifact. This applies to runs started with the split workflow; older runs do not gain a saved artifact retroactively.

**Deployment:** the workflow checks `../maps-rendered` from the Python working directory, then transfers `maps-rendered/` from the repository root with one archive path component stripped. SCP overwrites files without removing the remote maps directory referenced by site releases. Files absent from a later build remain on the server; obsolete asset cleanup is separate. The deployment account needs write access to the existing map files and directories.

**Invariants:** production output goes to `maps-rendered`; dev output goes to `jgantts-com/PUBLIC/assets/maps`. Hashes include raster/layer parameters. Staging survives through asset copying, including unchanged builds, and is cleaned on success or failure. Parent-region paths, bounds, zooms, and dark variants must agree with browser code. Generated outputs are not authoritative source rasters. The main script copies region JSON alongside compiled assets.

**3D elevation:** A region’s `terrain` configuration names its source height map, maximum tile zoom, and browser exaggeration. The incremental builder runs `tile_dem.py` to generate Mapbox RGB tiles under that region’s `height-tiles/` directory. Ziemúnd uses `height-eroded.png`, the existing 750–1500 m normalized elevation range, and tile zooms 0–8. Hashes include the source, bounds, tile zoom, and generator; any missing expected tile rebuilds the set. Local and production builds copy the tiles with the other map assets.
